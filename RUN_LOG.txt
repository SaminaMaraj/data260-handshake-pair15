2026-10-31  First real consolidation run (failed, then fixed)

1. Seeded student 1 with 62 memory entries (27 facts, 4 exact-duplicate
   groups, 5 contradictions) and published one message to
   p15.memory.consolidate.
2. Every model call timed out at 180 s (qwen3's thinking mode). After
   3 attempts the worker sent the message to p15.memory.consolidate.dlq.
3. Processing took longer than Kafka's max.poll.interval.ms (5 min), so
   Kafka removed the worker from its group. The commit failed with
   UNKNOWN_MEMBER_ID, the worker restarted, and the uncommitted message
   was redelivered again and again. No data was lost or duplicated.
   Log: docs/evidence/memory_worker_incident_oct31.log
4. Fix (commit 22263b1): worker-only model client with thinking off and
   a 600 s timeout, max.poll.interval.ms sized to the worst case (about
   32 min), failed commits logged instead of raised, and dead-lettered
   events recorded in processed_events so they are not retried.
